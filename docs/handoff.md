## Доступ к среде

- Консоли на машине пользователя (`device_bash`) нет. Работа — через файловый мост
  (`device_list_dir` / `device_stage_files` / `device_commit_files`); сборки и запуски
  QEMU выполняет пользователь сам и присылает вывод.
- **Правило для моста**: после `device_commit_files` иногда повторное чтение
  показывает старую версию файла. После каждой записи — перечитывать и сверять
  размер в байтах; при расхождении перезаписать с `force: true`.

## Текущий статус

- **Сборочная среда: готова.** i386 собирается от начала до конца
  (`make -C docker -f build.mk hdimage` → `minix_x86.img`). Отдельно не
  подтверждались: `qemu-hdimage` после фикса прав `/dev/kvm` и ARM-путь
  (`sdimage` / `qemu-sdimage`).
- **Текущий этап — модернизация (`docs/modernization.md`), ни один пункт ещё не
  начат.** Пункты: `kyield`; `kmutex`; абстрактные таблицы страниц; переделка SMP +
  спинлоки, SMP по умолчанию; ASID/PCID; U-Boot + fitImage вместо multiboot; аудит
  типов под 64 бита.
- Портирование на новые архитектуры — после этапа модернизации.

## Что уже видно по коду (первичный осмотр в этой сессии)

- `minix/servers/vm/pt.h`: `pt_t` жёстко двухуровневый и на `u32_t`.
- `minix/servers/vm/pagetable.c` (~1500 строк): около полусотни ветвлений
  `__i386__`/`__arm__` прямо в логике.
- `minix/kernel/spinlock.h`: простой спинлок на `atomic_t` + Big Kernel Lock; без
  `CONFIG_SMP` — пустые макросы. SMP собирается только с `CONFIG_SMP`
  (`minix/kernel/Makefile`, `arch/i386/Makefile.inc`), и есть только для i386.
