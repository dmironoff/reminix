Новое в этой части:

1. **Разобрана тупиковая ветка владельца**
   `/media/dmironov/…/reminix(тупик)` — **только чтение, ничего не менять**.
   22 коммита, 10.03–28.04.2026. Ядро последний раз собиралось в коммите
   `4202722`, после него всё «Нерабочая версия». Что там начато:
   - абстрактная карта памяти (`mmap_utils`) и APT (`apt_utils`,
     `arch/earm/pagetables.c`);
   - ASID (`arch_proc_context.c`), kmutex (`libkmutex`), kyield;
   - SMP (`resmp.c`, `trampoline.S`, GIC-400, `h3_cpu.c`);
   - загрузка на Allwinner H3 через U-Boot + fitImage + FDT;
   - перестройка BSP на `vendor/soc`;
   - скрипты образов для Orange Pi PC Plus, BeagleBone, RPi3;
   - старый VM удалён, есть заготовка `revm`.

   Вердикт: идеи в основном правильные, код почти целиком нерабочий. Сквозные
   ошибки:
   - выходные параметры передаются по значению;
   - перевёрнутые `memcpy`;
   - `switch` без `case` в `pg_init`;
   - `mpidr && 0xFF`;
   - `strex` с непосредственным операндом;
   - `sys_kyield` отправляет `SYS_EXIT`;
   - `head.S` затирает r11 (адрес DTB).

   Разбор нужен был только для обсуждения и планов; **отдельный документ по
   тупиковой ветке не делаем** (решение владельца). Уроки кратко вошли в
   `docs/memory.md` §9 и в правила плана выполнения.
2. **PSCI внесён в документацию**: решение «запуск вторичных CPU и

   INIT–SIPI на amd64) добавлено в п. 4 `modernization.md`. Подробности (FDT,

   - buddy в VM;
   - регионы VM с исправленными типами;
   - APT как журнал MAP / UNMAP / PROTECT в общей памяти (арена) с `kmutex`;
   - ленивое применение для расширяющих операций, синхронное (`VMCTL_AS_SYNC`)

   - транслятор `arch_pt_*` в `kernel/arch/<arch>/pt.c`;
   - шаги внедрения М1–М7.

   В `modernization.md` уточнены п. 2 (роль `kmutex`) и п. 3 (принятая схема).
   В `architecture.md` добавлен §2.2. Добавлена строка в `CLAUDE.md`.
4. **Принят план выполнения модернизации** (`modernization.md`, разделы

   - этап 0: тесты, аудит типов, `kyield`;
   - этап 1: направление А (i386: А1 типы → А2 bootmem → А3 buddy → А4 атомики и

## Доступ к среде

- Консоли на машине пользователя (`device_bash`) нет. Работа — через файловый мост
  (`device_list_dir` / `device_stage_files` / `device_commit_files`); сборки и запуски
  QEMU выполняет пользователь сам и присылает вывод.
- Подключены две папки: `…/reminix` (основной проект) и `…/reminix(тупик)`
  (**только чтение**).
- **Правило для моста**: после `device_commit_files` иногда повторное чтение
  показывает старую версию файла. После каждой записи — перечитывать и сверять
  размер в байтах; при расхождении перезаписать с `force: true`.

## Замечено в коде (для будущей работы)

- `minix/servers/vm/alloc.c`: битовая карта жёстко на 4 ГБ, номера страниц `int`.
- `minix/servers/vm/region.h`: `phys_block.refcount` — `u8_t`.
- `minix/servers/vm/pt.h`: `pt_t` жёстко двухуровневый, на `u32_t`;
  `pagetable.c` — ~50 ветвлений `__i386__`/`__arm__`.
- `minix/kernel/spinlock.h`: простой спинлок + Big Kernel Lock; SMP только с
  `CONFIG_SMP` и только для i386.
- `minix/lib/libmthread/pthread_compat.c`: `pthread_mutex_trylock` рекурсивно
  вызывает сам себя.
- libc без `_REENTRANT`, без TLS, `_lwp_*` в `MISSING_SYSCALLS`.
